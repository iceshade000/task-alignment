# 一次面向普通用户的医疗产品讨论

本案例用于解释方法为何有用。最终方向获得了讨论者认可，市场吸引力、临床收益和技术效果仍待验证。

## 讨论中逐步明确的目标与约束

团队确定要推进面向医生的影像研究，包括区域输入输出、多份影像综合理解和未来状态预测。希望低增量探索普通用户产品，且患者可以独立开始使用。普通用户缺乏医学知识，甚至不知道自己有哪些理解缺口，讨论将这种缺口视为恐惧和医嘱执行困难的重要来源。

## 对话怎样反复走偏

| 提议与反馈 | 暴露的前提 | 可迁移的改进 |
| --- | --- | --- |
| 从医生减负延伸出患者看片、对比和找位置的功能 | 沿用专业人员的任务观，没有抓住患者不知道该问什么的处境 | 分别分析角色的知识和理解障碍，检验同一能力对各方的实际收益 |
| 从报告解释扩展到随手拍，随后设计拍照记录与复拍 | 把用户探索的交互形态当成已经存在的习惯 | 先解释用户为什么愿意采取这个动作，再设计动作后的流程 |
| 反复提出看懂报告、知道下一步、判断是否就医 | 收益抽象，且默认工具也能提供类似结果 | 用合理强的替代方案检验剩余价值，重新寻找作用环节 |
| 查阅定位方法后，仍然提出通用问答能够完成的主张 | 学到的方法没有改变候选的取舍依据 | 把调研结论变成能淘汰或改进候选的具体判断，再继续生成 |
| 通过第二位专家的意见建立信任 | 额外引入专家供给与服务运营 | 把新增资源与现有技术复用分别计入方案 |
| 把医生圈好的病灶交给患者查看 | 将复用模型偷换成依赖医生先采用产品 | 从独立使用者的真实起点走一遍数据与参与条件 |
| 把病情做成可视讲解 | 解释更直观，却仍要求患者相信一个新增解释来源 | 明确解释依据、原始意见和未知，检验信任如何建立 |
| 用户提出“消除医患沟通障碍” | 关键问题从单次回答转向双方理解差异 | 分析关系和信息流，寻找谁说不清、谁误解、什么需要共同核对 |
| 用户补充保存交流、记录执行、复诊反馈 | 单次对话没有保存后续判断需要的信息 | 对连续任务检查结果如何进入后续行动，实际反馈如何更新判断 |
| 整理完整形态时遗漏医生向患者的主动解释 | 最新反馈挤掉了先前已经确认的一半目标 | 重写时按角色和信息方向检查覆盖，保留原有共识 |

核心主张和复诊反馈机制由用户明确提出。助手在前期持续输出候选，却未能自行找到这一转向，这是复盘应当保留的事实。

## 用关键对象和信息流寻找切口

用户进一步指出，可执行的方法是整理关键对象及其信息流动，判断是否顺畅、能否实现预期。此前“检查共同前提、重构问题”的指令缺少这样的中间结果，容易让模型继续泛泛生成方案。

本案中，医生掌握专业判断，患者掌握感受和日常经历，检查与医嘱保存一部分诊疗信息。预期是双方能够理解与本次诊疗有关的情况，支持行动，并根据实际结果继续判断。医生和患者各自拥有、需要的信息与理解能力不同。

| 信息流或使用环节 | 预期作用 | 需要检查的缺口 |
| --- | --- | --- |
| 患者的感受、经历传给医生 | 支持医生判断与追问 | 患者是否知道哪些信息重要，能否说清时间、部位和变化 |
| 医生的判断和医嘱传给患者 | 支持理解病情与后续安排 | 患者是否理解了原意，是否意识到仍需确认的内容 |
| 患者依据理解执行安排 | 将医嘱落实到日常行动 | 具体要求是否清楚，是否遇到能力或资源限制 |
| 执行情况与身体变化回到复诊 | 支持医生更新判断 | 是否留下记录，依据和时间是否清楚，能否说明实际差异 |

这样可以看到，专业意见与实际经历已经存在，表达、理解、执行及反馈之间仍有缺口。患者不知道该问什么，说明必要信息很难完全依赖患者主动索取，理解确认和主动澄清因此有具体用途。复诊需要知道实际执行和变化，也让连续记录有了明确目的。

从这些缺口出发，可以讨论帮助患者表达、辅助理解、保留执行过程等候选。把它们联系起来，形成了“消除医患沟通障碍”的产品方向。每一项功能都应能指出自己改变了哪条关系，为什么能改善双方的判断或行动。

## 从一处缺口写出具体候选

讨论中用过一个假设情境，医生说“本次稳定，继续随访”，患者理解为“以后不用管了”。缺口可以写成，患者需要依据医嘱安排后续行动，但在理解中把当前观察结论扩大为永久结论，因此忽略了仍需随访的要求。实际是否存在这种误解，需要核实。

一个候选操作是，患者提供已有医嘱，并用自己的话描述后续打算。系统比较两者含义，指出相应差异并附上原话，患者据此核对理解，或向医生确认仍有疑问的内容。确认后的说明和来源保留下来，支持后续行动及复诊。

这样就可以具体检验，比较一般医嘱摘要与理解核对后，患者是否更容易发现误解、形成与原医嘱相符的理解。系统指出差异的准确性、是否增加困扰也属于待检验内容。仅增加一份更长的说明，并未说明这条理解缺口怎样被处理。

类似地，复诊需要实际执行情况，而回忆可能不完整，可以产生围绕医嘱保留执行与变化的候选。记录须区分患者自述、其他证据及缺失信息。将这些改动连起来，才形成解释、理解确认、行动记录、复诊反馈和新意见更新的完整设想。

这份梳理用来解释方法。由已知结果倒推仍可能有事后偏差，独立测试应隐去最终答案和本案例，只提供当时线索与skill主文，检查是否能从对象和关系中找到有依据的新切口。

## 迁移时保留边界

- 本案例要求低增量投入、患者独立使用。其他任务可以合理依赖新的渠道、组织合作或用户行为，前提是明确成本与收益。
- 本案例围绕一个核心卖点收敛。面对多种购买者或复杂研究问题，价值结构可以相应展开。
- 连续诊疗适合双向反馈与长期记录。单次任务按其完成条件设计。
- 区域交互、多图与预测是本案技术资产。其他任务的优势可以来自性能、成本或组织方式。
- 获得讨论认可说明构想更贴合目标。实际采用、信任和效果需要相应证据。
